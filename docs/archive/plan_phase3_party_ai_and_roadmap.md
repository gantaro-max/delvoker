# Implementation Plan: Phase 3 Party AI and Roadmap Integration

1. **Task Overview:**
   Phase 3の核心である「パーティシステム」と「NPCのAI行動（癖）」の基盤を実装します。同時に、今後の開発を円滑にするため、提案された追加機能（高度な戦闘、自動生成、成長システムなど）を `4. 開発タスク.md` に正式なタスクとして組み込み、プロジェクト全体のドキュメントを同期させます。

2. **Target Files:**
   - `src/models/data.py`: パーティ管理およびNPCの性格（癖）データの追加。
   - `src/logic/battle.py`: 複数人戦闘への対応とAI行動ロジックの導入。
   - `docs/4. 開発タスク.md`: ロードマップの更新（提案機能の追加）。
   - `docs/1. 機能要件.md`: NPC AIおよび将来機能の追記。
   - `docs/2. 仕様詳細.md`: パーティ編成とAIの仕様を新規作成。

3. **Step-by-Step Instructions:**

   **Step 1: ロードマップとドキュメントの更新（優先）**
   - `docs/4. 開発タスク.md` の Phase 4/5 を、以下の提案内容を取り込んだ形に書き換えてください。
     - **戦闘深化:** マナ(MP)消費スキル、状態異常、ダメージポップアップ表示。
     - **マップ高度化:** ランダム生成(Procedural Generation)ロジック、階段/宝箱ギミック。
     - **成長深化:** レベルアップ時のステータスポイント手動割り振り、拠点（マイホーム）の永続強化。
     - **敵AI強化:** 遠距離攻撃、仲間を呼ぶ、ボス固有アルゴリズム。
   - `1. 機能要件.md` および `2. 仕様詳細.md` に、パーティ制限（最大3名）、性格別行動（Reckless/Cowardly/Selfish）、暴走確率（25%前後）の仕様を追記してください。

   **Step 2: データ構造の実装 (`src/models/data.py`)**
   - `CharacterStatus` クラスに `personality` (性格) フィールドを追加。
   - `Party` クラスを作成し、プレイヤー1名 + NPC最大2名を保持・管理できるようにします。

   **Step 3: AI行動ロジックの実装 (`src/logic/battle.py`)**
   - 戦闘中にNPCが指示されたコマンドではなく、性格に基づき一定確率で「勝手な行動」を選択する判定処理を追加してください。
   - 行動ログに `[Name] acts on their own!` と表示し、ASCII制約を守ったメッセージを出力してください。

4. **Constraints:**
   - すべての表示テキスト、性格名は ASCII文字のみを使用すること。
   - パーティ全員のHPが0になった際の全滅判定ロジックを含めること。

5. **Success Criteria:**
   - `docs/` 内の各ドキュメントが最新の提案内容で完全に同期されている。
   - 戦闘でNPCが加わり、確率で独自の行動をとることがログで確認できる。
   - パーティ管理機能により、複数人のステータスが正常に処理される。

6. **Archive Task:**
   - 全ての作業完了後、本ファイルを `docs/archive/` に移動してください。
