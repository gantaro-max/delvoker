# Implementation Plan: Phase 13 - Core Expansion (Segmented)

## 1. Task Overview
ゲームの核となる「視覚表現」「戦闘の戦略性」「長期的な成長要素」を大幅に強化します。
本フェーズは影響範囲が広いため、3つのサブフェーズに分割して進めます。
**各サブフェーズの完了ごとに、必ずソースコードの反映、ドキュメントの更新、およびユーザーへの完了報告を行ってください。**

## 2. Target Files
- `/workspaces/games/main.py`: 戦闘ロジック、描画メソッド、状態管理。
- `/workspaces/games/data.py`: モンスター、スキル、図鑑データ構造。
- `/workspaces/games/systems/persistence.py`: セーブデータ拡張。
- `/workspaces/games/ui/renderer_3d.py`: 描画拡張。
- `/workspaces/games/docs/3. 仕様詳細.md`: 仕様の追記。
- `/workspaces/games/docs/4. 開発タスク.md`: 進捗管理。

## 3. Sub-Phases & Instructions

### Phase 13.1: グラフィック・アセット化の基盤
**目的:** 矩形描画を卒業し、スプライト描画と視覚エフェクトを導入します。

1. **アセットロード:** `App.__init__` で `pyxel.load("assets.pyxres")` を実行。ファイル不在でもエラーにならないよう try-except でラップ。
2. **データ定義拡張:** `data.py` の `EnemyDef` および `ENEMY_CATALOG` にスプライトの座標 (u, v) フィールドを追加。
3. **描画切替:** `main.py` の `_draw_battle` において、敵の描画を `pyxel.rect` から `pyxel.blt` に変更。
4. **エフェクトシステム:** `Effect` クラス（x, y, timer, type）を導入し、攻撃ヒット時に火花などの簡易アニメーションを表示。
5. **ドキュメント更新:** `3. 仕様詳細.md` にスプライト仕様とエフェクトの仕組みを追記。
**[Check Point]** 13.1 完了後、敵がスプライトで表示されていることを確認し、ユーザーの承認を得ること。

### Phase 13.2: 戦闘システムの多対多への拡張
**目的:** 1対1から「パーティ vs 複数敵」へ戦闘システムを根幹から拡張します。

1. **設計提示:** 実装前に、`self.enemy` を `self.enemies` リストに変更することによる `main.py` の影響箇所（ターゲット選択、ターンループ、勝利判定等）の修正案をユーザーに提示し、承認を得ること。
2. **データ構造変更:** `App` クラスの戦闘関連プロパティをリスト対応に移行。
3. **ターゲットUI:** 複数体いる敵から攻撃対象を選択するカーソル移動・決定ロジックの実装。
4. **アクティブスキル:** `Skill` クラスを拡張し、ジョブごとの固有スキル（Warrior: Provoke, Thief: Poison Stab等）を実装。
5. **ドキュメント更新:** `3. 仕様詳細.md` の戦闘セクションを多対多・スキル仕様に合わせて刷新。
**[Check Point]** 13.2 は最もリスクが高いため、設計提示フェーズと実装完了フェーズの2回、ユーザー確認を行うこと。

### Phase 13.3: メタプログレッションと図鑑システム
**目的:** プレイヤーの歩みを記録し、永続的なコレクション要素を追加します。

1. **永続化拡張:** `systems/persistence.py` およびセーブデータ形式を更新し、`bestiary` (敵ID -> 撃破数) を保持可能にする。旧セーブデータの読み込み互換性を維持すること。
2. **記録ロジック:** 戦闘終了時の勝利判定（`_handle_victory`）で撃破数をカウントアップ。
3. **図鑑UI:** 拠点（Home）に「Bestiary」サブメニューを追加。遭遇済みの敵の能力値や耐性を閲覧できる画面を実装。
4. **ドキュメント更新:** `3. 仕様詳細.md` に図鑑システムとセーブデータ拡張仕様を追記。
**[Check Point]** 13.3 完了後、セーブ/ロードが正しく行われ、図鑑が更新されることを確認して完了報告。

## 5. Constraints
- **ASCII維持**: 日本語化（Issue 4）は将来課題とするため、コード内および現在のログ出力は ASCII のみを維持すること。
- **1ファイルずつの修正**: Claude Code は、一度に大量のファイルを修正せず、1ステップごとに確実にコードを確定させること。

## 6. Success Criteria
1. 戦闘で複数の敵が出現し、個別に撃破できる。
2. 敵が矩形ではなく、スプライト（blt）で表示されている。
3. 撃破した敵の情報がセーブされ、拠点の図鑑メニューで確認できる。
4. `docs/4. 開発タスク.md` の Phase 13 関連のチェックボックスがすべて埋まっている。
