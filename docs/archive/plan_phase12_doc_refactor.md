# Implementation Plan: Documentation Refactoring & Consolidation

## 1. Task Overview
プロジェクトの規模拡大に伴い、重複・散逸しているドキュメントを整理・校正します。
「ユーザー視点の要件」「システムの詳細仕様」「非機能制約」を明確に分離し、開発の「唯一の真実（Single Source of Truth）」としての精度を高めます。

## 2. Target Files
- `docs/1. 機能要件.md`: 内容の軽量化と概要への特化。
- `docs/2. 非機能要件.md`: 命名の維持と内容の整合性確認。
- `docs/3. 仕様詳細.md`: 旧 `2. 仕様詳細.md` から改名。ロジック・計算式・データ構造を集約。
- `docs/4. 開発タスク.md`: フェーズステータスの更新。
- `docs/Delvoker_Specification.md`: `1. 機能要件.md` との統合後に削除（アーカイブ）。

## 3. Step-by-Step Instructions

### Step 1: ファイル構成と番号の整理
- `docs/2. 仕様詳細.md` を `docs/3. 仕様詳細.md` にリネームします。
- これにより、1:機能要件、2:非機能要件、3:仕様詳細、4:開発タスク という連番構成にします。

### Step 2: 機能要件の整理 (`1. 機能要件.md`)
- 「実装済み」などの開発メモを削除します。
- `Delvoker_Specification.md` の企画内容を統合し、ゲームの目的と機能一覧を簡潔にまとめます。
- ダメージ計算式やエンチャント表などの技術的な詳細は、Step 3 で整理する「仕様詳細」に移譲し、ここでは概要のみを記述します。

### Step 3: 仕様詳細の体系化 (`3. 仕様詳細.md`)
- 旧 `2. 仕様詳細.md` をベースに、以下のカテゴリで再構成します：
    - 1. コアシステム（パーティ、ステータス、永続化）
    - 2. 戦闘システム（AI、ダメージ計算式、状態異常）
    - 3. 装備・属性システム（エンチャント、相性表）
    - 4. 探索・マップシステム（生成アルゴリズム、タイル種別）
    - 5. 街・拠点システム（施設機能）
    - 6. 技術・ファイル構成（リファクタリング後の最新構成）
- すべての計算式（ダメージ計算、倉庫拡張費用、Training費用）をここに集約します。

### Step 4: 開発タスクの更新 (`4. 開発タスク.md`)
- Phase 11 を「完了」にマークします。
- Phase 12 に「ドキュメントの整理と校正」を追加し、着手状態にします。

## 4. Constraints
- **ASCII制約**: ゲーム内表示に関連する単語（アイテム名、スキル名、ログ等）の記述は必ず半角英数字（ASCII）を維持してください。
- **一貫性**: `constants.py` や `data.py` の実際のコードとドキュメント内の定数名・クラス名が一致していることを確認してください。

## 5. Success Criteria
1. `docs/` 内のファイルが 1, 2, 3, 4 の連番で整理されている。
2. `1. 機能要件.md` から複雑な計算式が排除され、`3. 仕様詳細.md` に一元化されている。
3. すべてのドキュメントから「Phase X 実装済み」といった一時的なメモが消去され、完成された仕様書になっている。
4. リンク切れやファイル参照の矛盾がない。
