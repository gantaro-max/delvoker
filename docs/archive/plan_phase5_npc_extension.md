# 1. Task Overview
Phase 5 の最初のステップとして、NPC のカスタマイズ性を大幅に強化します。
1. プレイヤーのインベントリから NPC へアイテムを渡す機能を実装。
2. NPC が独自の装備スロット（Weapon/Armor）を持ち、ステータスに反映されるように変更。
3. 戦闘中、未昇格 NPC（AI行動）が性格や状況に応じて所持スキルを自律的に使用するロジックを実装。

# 2. Target Files
* `data.py`: `NPCMember` クラスの装備管理ロジック、`total_def` の確認、**`Party` クラスへの `fallen` プロパティ追加**。
* `main.py`: アイテムアクションメニューへの「Give to NPC」追加、AI行動ロジック (`_npc_combat_action`) の拡張、**町での復活サービス関連のロジック (`_upd_revive`, `_draw_revive`) とUIステートの追加**。
* `docs/2. 仕様詳細.md`: NPC AI のスキル使用優先順位の追記。
* `docs/4. 開発タスク.md`: Phase 5 タスクの進捗更新。


# 3. Step-by-Step Instructions

## 3.1 NPC 装備システムの実装
1.  **データ構造の確認 (`data.py`):**
    *   `NPCMember` は `Status` を継承しているため、既に `weapon` と `armor` フィールドを持っていることを確認。
    *   `Status.total_def` が `self.armor.def_bonus` を加算する仕様になっているか再確認し、NPCにも適用されるようにする。
2.  **アイテム授与機能 (`main.py`):**
    *   `STATE_INV_ACTION` にて、対象アイテムが装備品（Weapon/Armor）の場合に「Give to NPC」メニューを表示する。
    *   NPC を選択させ、選択された NPC の `weapon` または `armor` を更新する。
    *   NPC が元々装備していたアイテムは、プレイヤーのインベントリに戻す（満杯の場合は警告を出し、実行不可とする）。

## 3.2 高度 AI（スキル使用）の実装
1.  **AI行動の拡張 (`main.py` -> `_npc_combat_action`):**
    *   NPC が `skills` を所持しており、かつ MP が足りる場合、一定確率（性格に応じた確率）でスキルを使用するように変更。
    *   **性格別ロジック:**
        *   `reckless`: 攻撃スキルを優先。MPがある限り 40% の確率で使用。
        *   `cowardly`: 味方の誰かの HP が 50% 以下の時、回復スキルがあれば 80% の確率で使用。それ以外は防御を優先。
        *   `normal`: 状況に応じて 20% の確率でスキルを使用。

## 3.4 町での復活サービス（寺院）の実装

**目的:**
町に「Revive（復活）」メニューを追加し、HPが0になったパーティメンバーをゴールドを支払って蘇生・回復できる仕組みを導入する。

**実装詳細:**
1.  **データ構造の拡張 (`data.py`)**:
    *   `Party` クラスに、死亡しているメンバーのみを抽出する `fallen` プロパティを追加すること。
        ```python
        @property
        def fallen(self) -> list:
            return [m for m in self.members if m.hp <= 0]
        ```
2.  **UIとステートの追加 (`main.py`)**:
    *   `STATE_REVIVE` (値: 13) を定義し、`TOWN_MENU` に `"Revive"` を追加すること。
    *   `App` クラスの `__init__` メソッドで `self.revive_idx = 0` を初期化すること。
    *   `_set_state` メソッドで `STATE_REVIVE` 遷移時に `sub_win` を開き、他のウィンドウを閉じるように設定すること。
3.  **復活ロジックの実装 (`main.py`)**:
    *   `_upd_revive()` メソッドを新設する。
    *   `party.fallen` が空でない場合、上下キーで死亡メンバーを選択できるようにすること。
    *   Zキー押下時、選択されたメンバーの復活費用（`対象レベル * 100ゴールド`）を計算し、所持金が足りるか確認すること。
    *   所持金が足りる場合、ゴールドを消費し、対象メンバーのHPとMPを最大値まで回復させること。復活後、`self.revive_idx` を 0 にリセットすること。
    *   Xキー押下時、`STATE_TOWN` に戻ること。
    *   死亡メンバーがいない場合、Zキーまたはスペースキーで `STATE_TOWN` に戻ること。
4.  **描画処理の実装 (`main.py`)**:
    *   `_draw_revive()` メソッドを新設し、`sub_win` 内に「== TEMPLE of REVIVAL ==」メニューを描画すること。
    *   死亡メンバーのリスト、各メンバーの復活費用、現在の所持金、操作ガイド（Z:Revive, X:Back）を表示すること。
    *   復活費用が足りないメンバーは、名前の色を `COL_DARK_GRAY` にすること。
    *   死亡メンバーがいない場合は「Everyone is healthy.」と表示すること。

# 4. Constraints
* **UI:** NPC 選択時は既存のパーティメンバーリスト形式の UI を使用。
* **ASCII:** ログ表示 `[Skill] {NPC} uses {SkillName}!` 等は ASCII 文字のみ。
* **復活費用表示:** 復活費用は `対象レベル * 100G` とし、`COL_YELLOW` で表示する。

# 5. Success Criteria
1. プレイヤーのインベントリから NPC に装備を渡すと、NPC のステータスが更新される。
2. NPC が元々持っていた装備が、プレイヤーのインベントリに正しく戻される。
3. 戦闘中、NPC が性格に基づいたスキル（Attack/Heal）を自動で使用し、MP が消費される。
4. `docs/` 内の仕様書に AI 行動の詳細が反映されている。
5. **町メニューに「Revive」が表示され、選択できる。**
6. **「Revive」メニューで死亡しているパーティメンバーが表示され、復活費用が確認できる。**
7. **十分なゴールドがある場合、メンバーを選択してZキーを押すと、ゴールドが消費され、そのメンバーがHP/MP全回復で復活する。**
8. **ゴールドが足りない場合、復活できない。**
9. **死亡メンバーがいない場合、「Everyone is healthy.」と表示される。**
10. **Xキーで町メニューに戻れる。**
