# 仕様詳細

本ドキュメントはDelvokerの実装仕様をシステム別にまとめた技術リファレンスです。
計算式、データ構造、アルゴリズムをここに一元管理します。

---

## 1. コアシステム

### 1.1 パーティ構成

| 役割 | クラス | 最大人数 |
| :--- | :--- | :---: |
| プレイヤー | `Player` (extends `Status`) | 1 |
| 臨時NPC | `NPCMember` (extends `Status`) | 3 |
| **パーティ合計** | `Party` | **4** |

### 1.2 Party クラス仕様 (`data.py`)

| メンバー / プロパティ | 型 | 説明 |
| :--- | :--- | :--- |
| `members` | `list[Status]` | index 0 = プレイヤー、以降 NPC |
| `add(member)` | `bool` | 満員時 `False`、追加成功時 `True` |
| `is_wiped_out` | `bool` | 全員 HP ≤ 0 なら `True`（全滅判定） |
| `alive` | `list[Status]` | HP > 0 のメンバー一覧 |
| `fallen` | `list[Status]` | HP ≤ 0 のメンバー一覧（死亡メンバー） |
| `MAX_SIZE` | `int` | `4`（定数） |

### 1.3 NPCMember クラス仕様 (`data.py`)

```
NPCMember(job_key, name, personality)
```

| フィールド | 型 | 有効値 / 説明 |
| :--- | :--- | :--- |
| `personality` | `str` | `"normal"` \| `"reckless"` \| `"cowardly"` \| `"selfish"` |
| `inventory` | `list` | アイテム所持 |
| `is_unique` | `bool` | `False`（デフォルト）/ `True` = 固有NPC（手動操作可能） |

### 1.4 固有NPC昇格システム

- **場所:** ギルド画面（街メニュー > Guild）
- **費用:** `PROMOTION_COST = 1000G`
- **効果:** `npc.is_unique = True` に設定
- **戦闘での変化:** 昇格済み固有NPCは `STATE_BATTLE_NPC_CMD` でコマンド選択（Aid / Skill / Flee）を選べる。未昇格NPCは引き続きAI自動行動。

### 1.5 ステータス割り振りシステム

- `Status.bonus_points`: レベルアップ1回につき +3 加算。
- 消費: 任意のステータスを +1 するたびに -1。
- 対象ステータス: STR / DEF / AGI / MAG。

### 1.6 永続化（セーブデータ）

- **保存形式:** JSON (`delvoker_save.json`)
- **保存タイミング:** 街帰還時、Training強化時、エンディング到達時
- **保存対象:** 所持金、倉庫（アイテム・容量）、永続強化ステータス、解放済みジョブ、クリアフラグ
- **担当モジュール:** `systems/persistence.py`（`save_game` / `load_game`）

### 1.7 幸運値 (LUK)
- 影響範囲: クリティカル発生率 (`LUK %`)、逃走成功率補正、罠回避判定。
- 成長: ジョブごとの LUK 成長率に基づき上昇。アクセサリーで補正可能。

## 2. 戦闘システム

### 2.1 ダメージ計算式（Wiz風ハイブリッド方式）

```
基礎ダメージ = max(1, (dice_count × Random(1, dice_sides)) + static_bonus + enchant_bonus - target.DEF)
クリティカル判定 = Random(1, 100) <= attacker.LUK ? 2.0 : 1.0
最終ダメージ = max(1, int(基礎ダメージ × 属性倍率 × クリティカル判定))
```

| パラメータ | 説明 | 例 |
|---|---|---|
| `dice_count` | 振るダイスの個数 | 2 |
| `dice_sides` | ダイス1個の面数（最大値） | 6 |
| `static_bonus` | 武器固有の固定加算値 | +3 |
| `enchant_bonus` | 接頭辞・接尾辞が付与するボーナス | +5 |
| `DEF` | 対象のダメージ軽減値 | 2 |

### 2.2 属性倍率（優先順位順）

| 優先順位 | 条件 | 倍率 |
| :--- | :--- | :---: |
| 1 | `weapon.attribute` in `target.weaknesses` | ×1.5 |
| 2 | `weapon.attribute` in `target.resistances` | ×0.5 |
| 3 | `ATTR_AFFINITY[weapon.attribute]` in `target.resistances` | ×1.5 |
| 4 | `weapon.attribute == "holy"` かつ耐性なし | ×1.2 |
| 5 | その他 | ×1.0 |

### 2.3 多対多戦闘フロー（Phase 13.2）

**敵管理:**

| 変数 | 型 | 説明 |
| :--- | :--- | :--- |
| `App.enemies` | `list[Enemy]` | 戦闘中の全敵。`_start_battle` で初期化。撃破時に `_handle_victory(msgs, enemy)` 内で除去 |
| `App.target_idx` | int | `STATE_BATTLE_TARGET` で選択中の敵インデックス |
| `App._attack_target` | Enemy\|None | プレイヤーが選択した攻撃対象（TARGET → TARGET_PART の引き継ぎ用） |
| `App.telegraphing` | `dict[int, bool]` | 各敵の予兆フラグ（key: `id(enemy)`） |

**攻撃ターゲット選択フロー:**

```
STATE_BATTLE_CMD [Aid]
  ├─ enemies が複数 → STATE_BATTLE_TARGET（↑↓でカーソル、Zで決定、Xでキャンセル）
  │      └─ 決定後 → 部位あり → STATE_BATTLE_TARGET_PART → _player_attack(target, part)
  │                 → 部位なし → _player_attack(target)
  └─ enemies が1体 → （従来フロー）部位あり → STATE_BATTLE_TARGET_PART
                                          → 部位なし → _player_attack(enemies[0])
```

**敵出現数決定ロジック（ランダムエンカウント時）:**

| フロア範囲 | 1体 | 2体 | 3体 |
| :---: | :---: | :---: | :---: |
| B1F–B2F | 100% | — | — |
| B3F–B5F | 70% | 30% | — |
| B6F以降 | 60% | 30% | 10% |

ボス・イベント戦闘（`enemy_key` 指定）は常に1体。

**敵ターン:**
- `_enemy_turn` は `for acting_enemy in self.enemies:` ループで全敵が順番に攻撃
- 毒ダメージはループ外で1回適用（ラウンドに1回）

**勝利判定:**
- `_handle_victory(msgs, enemy)` — 撃破した敵を渡す
- 関数内で `self.enemies.remove(enemy)` を実行
- exp/gold は撃破した敵オブジェクトから取得

**描画レイアウト:**
- `n = len(self.enemies)` で水平スロット均等分割: `slot_w = SCREEN_W // n`
- 各スロット中心 `cx = slot_w // 2 + i * slot_w` にスプライト/名前/HP バー
- `STATE_BATTLE_TARGET` 中は選択中の敵の HP バー下に `^` カーソルを表示

### 2.4 敵 AI 行動タイプ

| ai_type | ターゲット選択ロジック |
| :--- | :--- |
| `"normal"` | `random.choice(party.alive)`（生存メンバーからランダム） |
| `"ranged"` | AGI が最高の生存メンバーを攻撃 |
| `"support"` | HP が最低の生存メンバーを攻撃 |

### 2.5 ボス予兆（telegraph）

- 設定されているボス敵は 30% の確率で強力攻撃の1ターン前に警告メッセージを表示。
- 次ターンは 2倍ダメージの攻撃（`[POWER]`）を実行。

### 2.6 NPC AI 自動行動ロジック

| 性格 | キー | スキル使用条件 | スキル発動確率 | 通常行動 |
| :--- | :--- | :--- | :---: | :--- |
| 無謀 | `reckless` | 攻撃スキル所持 + MP 足りる | **40%** | 通常攻撃 |
| 臆病 | `cowardly` | 回復スキル所持 + MP 足りる + 味方 HP 50%以下 | **80%** | 行動スキップ |
| 普通 / 利己的 | `normal` / `selfish` | スキル所持 + MP 足りる | **20%** | 通常攻撃 |

**スキル選択ロジック:**
- `reckless`: `effect_type == "attack"` のスキルのみ対象。ランダムに1つ選択。
- `cowardly`: `effect_type == "heal"` のスキルのみ対象。HP 最低の味方を回復。
- `normal`: 攻撃 or 回復スキルをランダム選択。回復時は HP 最低の生存メンバーを対象。

**スキルダメージ / 回復量:** `max(1, skill.power + npc.mag)`

### 2.7 ダメージポップアップ

| 種別 | 色 |
| :--- | :--- |
| 通常ダメージ | 白 (7) |
| 弱点ヒット | 黄 (10) |
| 被ダメージ | 赤 (8) |
| 回復 | 緑 (11) |

### 2.8 状態異常

| 異常 | フィールド | 効果 | 付与例 |
| :--- | :--- | :--- | :--- |
| 毒 | `status_effects["poison"]` | 敵ターン終了時に2ダメージ、残ターン-1 | Slime (30%) |
| スタン | `status_effects["stun"]` | プレイヤーの行動を1ターンスキップ | Skeleton (20%) |

戦闘画面HPバー横に `[P]`（毒: 緑）・`[S]`（スタン: 黄）を表示。

### 2.9 バトルログビューア（Phase 19）

| 項目 | 内容 |
| :--- | :--- |
| 状態 | `STATE_LOG_VIEW = 23` |
| 起動キー | 戦闘関連ステート中に `L` |
| 終了キー | `L` または `X` |
| 履歴 | `App.message_history` に最大100行保持 |
| 保存タイミング | `_show_msgs(messages, next_state, colors=None)` 呼び出し時 |
| スクロール | Up/Down: 1行、Left/Right: ページ単位 |

**ポーズ仕様:** `STATE_LOG_VIEW` 中は `update()` 冒頭で `_upd_log_view()` のみを実行して return する。敵ターン、毒ダメージ、ポップアップ、エフェクト、画面揺れなどのフレーム進行は停止する。

**復帰仕様:** ログ起動前の戦闘ステートを `App.log_return_state` に保存し、終了時に同じステートへ戻る。`STATE_BATTLE_MSG` から開いた場合も `msg_idx` は保持される。

## 3. 装備・属性システム

### 3.1 ATTR_AFFINITY 定数 (`data.py`)

```python
ATTR_AFFINITY = {"fire": "ice", "ice": "poison", "poison": "fire"}
```

`ATTR_AFFINITY[A] = B` は「A は B 属性を持つ対象に特効」を意味する（三すくみ）。

### 3.2 武器エンチャント

データ定義: `data/enchants.json`

**接頭辞（Prefix）：ダメージ数値を変化させる**

| キー | 名称 | 効果 | ウェイト |
| :--- | :--- | :--- | :---: |
| `sharp` | Sharp | `dice_sides` + 2 | 30 |
| `heavy` | Heavy | `static_bonus` + 3 | 30 |
| `master` | Master | `dice_count` + 1 | 10 |
| `cursed` | Cursed | `dice_count` - 1 | 20 |

**接尾辞（Suffix）：属性を付与する**

| キー | 名称 | 属性 | ウェイト |
| :--- | :--- | :--- | :---: |
| `fire` | +Fire | fire | 20 |
| `ice` | +Ice | ice | 20 |
| `poison` | +Poison | poison | 15 |

**レアリティ色分け:**

| ランク | 条件 | 色定数 |
| :--- | :--- | :--- |
| normal | エンチャントなし | `COL_WHITE` (7) |
| rare | 接頭・接尾のどちらか1つ | `COL_YELLOW` (10) |
| epic | 接頭・接尾の両方が付与 | `COL_PEACH` (15) |
| legend | Master など強力な組み合わせ | `COL_ORANGE` (9) |
| genesis | 接頭・接尾なし、高基礎性能 | `COL_BLUE` / `COL_WHITE` 明滅 |

| `attribute` | `str \| None` | 付与属性（装備者の耐性に自動追加） |

| キー | 名称 | 効果 | ウェイト |

**接尾辞（armor_suffixes）:**

| キー | 名称 | 耐性属性 | ウェイト |

## 5. 探索・マップシステム

### 5.1 Map クラス仕様 (`logic/map_generator.py`)

| メソッド / プロパティ | 説明 |
| :--- | :--- |
| `generate_random(width=20, height=20)` | 部屋と通路アルゴリズムでランダムマップを生成 |
| `is_wall(x, y)` | 壁判定（範囲外も True） |
| `tile_at(x, y)` | タイル種別を返す（範囲外は TILE_WALL） |
| `visit(x, y)` | `visited[y][x] = True` に設定 |
| `set_tile(x, y, tile)` | タイル書き換え（宝箱開封後の FLOOR 化に使用） |
| `start_x, start_y` | 最初の部屋の中心座標 |

### 5.2 生成アルゴリズム概要

1. 全タイルを `TILE_WALL` で初期化
2. 25 回ランダムに部屋を試行配置（重複チェックあり）
3. 隣接する部屋の中心を水平→垂直の通路で接続
4. 最後の部屋の中心に `TILE_STAIRS` を配置
5. 中間の部屋に `TILE_CHEST` / `TILE_FOUNTAIN`（50%）/ `TILE_MERCHANT`（B3F以降 20%）を確率配置
6. 通路チョークポイントを検出し、最大2か所に `TILE_LOCKED_DOOR` を 30% 確率で配置
7. 鍵扉が存在する場合、`rooms[1]` に `TILE_CHEST`（key_chest_pos）を追加して `dungeon_key` を保証

### 5.3 階層別生成ルール (Phase 15 リバランス)

トラップ数、鍵扉数、鍵チェスト保証は Phase 15 で調整済み。詳細な数値は「13. 階層別マップ生成ルール」を正とする。

### 5.4 エンカウント計算式

連続エンカウントを防止するため、歩数ベースの傾斜確率を導入。計算式と歩数レンジは「12. エンカウント・平滑化仕様」を正とする。

### 5.5 タイル種別一覧

| 名称 | 定数 | 値 | ミニマップ色 | 効果 |
| :--- | :--- | :---: | :---: | :--- |
| 床 | `TILE_FLOOR` | 0 | グレー (5) | 通常移動 |
| 壁 | `TILE_WALL` | 1 | — | 移動不可 |
| 階段 | `TILE_STAIRS` | 2 | 黄 (10) | 次の階層へ進行 |
| 宝箱 | `TILE_CHEST` | 3 | 橙 (9) | アイテム入手。20%でミミック |
| 棘トラップ | `TILE_TRAP_SPIKE` | 4 | グレー (5) | 5〜10 ランダムダメージ |
| 毒針トラップ | `TILE_TRAP_POISON` | 5 | グレー (5) | 毒 3 ターン付与 |
| 遺品 | `TILE_GRAVE` | 6 | ピンク (14) | 守護者を倒してロストアイテム回収 |
| 鍵扉 | `TILE_LOCKED_DOOR` | 7 | インディゴ (13) | Dungeon Key で開錠 → TILE_FLOOR に変換 |
| 泉 | `TILE_FOUNTAIN` | 8 | 青 (12) | 70%で30%回復、20%で空振り、10%で毒。使用後 FLOOR 化 |
| 商人 | `TILE_MERCHANT` | 9 | 緑 (11) | 割高価格で貴重品を販売。使用後 FLOOR 化 |

### 5.6 部位破壊システム

- 戦闘中に本体とは別に部位をターゲット可能（`STATE_BATTLE_TARGET_PART`）。
- `Enemy.part_hps` で各部位の残HPを追跡。ダメージは本体HPと部位HP両方に同量適用。
- 部位HPが0になると `Enemy.broken_parts` に追加し、`[PART BROKEN: {name}]` をログ表示。
- 勝利時、破壊済み部位の `drop_flag` に対応するアイテムを 20% 確率で別枠ドロップ。

### 5.7 Grave クラス（遺品回収）(`data.py`)

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `floor` | `int` | 遺品が存在するフロア番号 |
| `x` | `int` | 遺品のマップX座標 |
| `y` | `int` | 遺品のマップY座標 |
| `item` | `Item` | ロストしたアイテムオブジェクト |

全滅時に `TILE_GRAVE` を配置。その座標に移動すると守護者 `revenant`（HP:40, DEF:2, 弱点:holy）との戦闘が発生し、勝利でアイテムを復元。

## 6. 街・拠点システム

### 6.1 復活サービス（`STATE_REVIVE = 13`）

| 項目 | 内容 |
| :--- | :--- |
| 費用計算 | `対象メンバーのレベル × 100 ゴールド` |
| 費用表示色 | `COL_YELLOW`（支払い可能）/ `COL_DARK_GRAY`（不足） |
| 復活効果 | 対象メンバーの HP・MP を最大値に全回復 |

### 6.2 NPC 装備管理 (`STATE_INV_GIVE_NPC = 14`)

1. アクションメニューで「Manage NPC Gear」選択 → NPC 選択画面へ遷移
2. 画面に「選択アイテム」と「対象 NPC の現在 W / A / Acc」を表示
3. Z 決定 → 対象 NPC の該当スロット（weapon / armor / accessory）に装備
4. 旧装備は自動的にプレイヤーの BAG へ返却
5. 武器・防具・アクセサリーすべてのスロットを管理可能（weight_class 制限なし）

### 6.3 拠点（Home）システム (`STATE_HOME = 15`)

#### Warehouse（倉庫）

| 変数 | 型 | 説明 |
| :--- | :--- | :--- |
| `Player.warehouse` | `list[Item]` | 倉庫保管アイテムリスト |
| `Player.warehouse_max` | `int` | 倉庫最大容量（初期値 10） |

左右キーで BAG/STORAGE を切り替え、上下キーで選択、Z で移動。

#### Renovate（倉庫拡張）費用

| 段階 | 費用 | 拡張後容量 |
| :---: | ---: | :---: |
| 1 | 500G | 15 |
| 2 | 1000G | 20 |
| 3 | 2000G | 25 |
| 4 | 4000G | 30 |
| 5 | 8000G | 35 |

現在段階 = `(warehouse_max - 10) // 5`。上限 35（5段階）。

#### Training（永続ステータス強化）費用

| 対象 | 効果 | 費用計算 |
| :--- | :--- | :--- |
| `perm_stats["str"]` | 攻撃ダメージに加算（`_player_attack` 内） | `(現在値+1) × 1000G` |
| `perm_stats["def"]` | `Player.total_def` に加算 | `(現在値+1) × 1000G` |

### 8.2 敵スプライト仕様

- **スプライトサイズ:** 32 × 32 ピクセル
- **イメージバンク:** Bank 0
- **透過色:** カラーインデックス 0（黒）
- **描画呼び出し:** `pyxel.blt(x, y, 0, sprite_u, sprite_v, 32, 32, 0)`。左右反転時は `w = -32` を使用
- **表示位置:** 敵エリア（ex=88, ey=28, ew=80, eh=70）中央に配置
- **制作方針:** 背景は色0で透過し、外縁に白・薄グレーなどの明部を少量入れて黒背景上の視認性を確保する。基本色に緑(3)・濃緑(11)を含めると階層別パレットスワップが分かりやすい。

**スプライトシートレイアウト（32×32グリッド）:**

| 敵キー | sprite_u | sprite_v |
| :--- | ---: | ---: |
| slime | 0 | 0 |
| bat | 32 | 0 |
| skeleton | 64 | 0 |
| goblin | 96 | 0 |
| orc_chief | 128 | 0 |
| revenant | 160 | 0 |
| wraith | 192 | 0 |
| golem | 224 | 0 |
| mimic | 0 | 32 |
| wyvern | 32 | 32 |
| dungeon_master | 64 | 32 |
| archdemon | 96 | 32 |

**データ定義:** `data/enemies.json` の各エントリに `"sprite_u"` / `"sprite_v"` フィールドとして記述。`EnemyDef` および `Enemy` クラスに対応属性を追加済み。

**診断仕様:** `_draw_enemy_sprite(enemy, x, y)` は `assets_loaded = False`、座標不正、`pyxel.blt` 失敗時に敵キー単位で一度だけコンソール警告を出し、32×32の矩形フォールバックを描画する。フォールバックには枠線と敵名の頭文字を表示し、スプライトが表示できない場合でも戦闘画面上の敵位置を確認できる。

### 8.2.1 階層別パレットスワップ（Phase 19）

敵描画は `main.py` の `_draw_enemy_sprite(enemy, x, y)` に集約する。

| 条件 | 置換方針 |
| :--- | :--- |
| B1F-B3F | 通常色 |
| B4F-B6F | 緑系を青・紺系へ置換し寒色バリエーション化 |
| B7F-B10F | 緑系を赤・紫系へ置換し強敵感を演出 |
| ボス (`orc_chief`, `dungeon_master`, `archdemon`) | ピンク・紫・橙を含む専用配色 |

**重要:** `pyxel.pal(orig, new)` 使用後は、敵スプライト描画直後に必ず引数なしの `pyxel.pal()` を呼び出してリセットする。これを怠るとUI・テキスト・メニューの色も置換される。

### 8.2.2 左右反転描画（Phase 19）

- `Enemy.__init__` で `flip_x = random.random() < 0.5` を設定する。
- 同一戦闘中は向きを固定し、毎フレーム再抽選しない。
- `flip_x == True` の場合は `pyxel.blt(x + 32, y, 0, sprite_u, sprite_v, -32, 32, 0)` で描画する。
- HPバー、名前、ターゲットカーソルなどのUI座標は反転で変更しない。

### 8.3 エフェクトシステム

**`Effect` クラス（`main.py` 内定義）:**

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `x` | int | スクリーンX座標 |
| `y` | int | スクリーンY座標 |
| `timer` | int | 残存フレーム数（初期値: 20） |
| `type` | str | エフェクト種別（現在: `"spark"` のみ） |

**動作フロー:**
1. プレイヤー攻撃ヒット時（`_player_attack`）に `Effect(128, 63, "spark")` を `self.effects` リストへ追加
2. `update` 内でフレームごとに `timer` をデクリメント。`timer == 0` になったエントリを除去
3. `_draw_battle` 内でエフェクトを描画（popupより手前のレイヤー）

**`"spark"` エフェクト描画:**
- `timer > 10` の前半: `COL_YELLOW`（明るい火花）
- `timer <= 10` の後半: `COL_ORANGE`（消えかけの残光）

## 10. アクティブスキル仕様 (Phase 14.2)

### 10.1 ジョブ固有初期スキル

| ジョブ | スキル名 | MP消費 | effect_type | 効果 |
| :--- | :--- | :---: | :--- | :--- |
| Warrior | Provoke | 3 | `provoke` | 敵ターゲットをプレイヤーに固定、2ターン間被ダメージ25%軽減 |
| Thief | Quick Strike | 4 | `quick_strike` | 武器ダイスダメージ + AGI/2 |
| Mage | Mana Bolt | 5 | `mana_bolt` | MAG × power(3) の固定魔法ダメージ |

- スキルはジョブ選択時（`_upd_job_select`）に `_grant_job_skill(job_key)` で自動付与される。
- Clericなどスキル未定義ジョブはスキル付与なし。

### 10.2 スキル計算式

**Provoke** (`effect_type="provoke"`, `power=2`)
```
player.status_effects["provoke"] = power  # 2ターン
効果: _get_enemy_target() → 常にプレイヤーを返す
      dmg × 0.75 (プレイヤーが受けるダメージに適用)
ターン終了ごとに provoke -= 1
```

**Quick Strike** (`effect_type="quick_strike"`)
```
dmg = max(1, weapon.roll_damage() + agi // 2)
対象: 選択した1体の敵
```

**Mana Bolt** (`effect_type="mana_bolt"`, `power=3`)
```
dmg = max(1, mag * power)
対象: 選択した1体の敵（防御無視の魔法ダメージ）
```

**Grimoire汎用攻撃スキル** (`effect_type="attack"`)
```
dmg = max(1, skill.power + mag)
対象: 選択した1体の敵
```

### 10.3 状態遷移フロー

```
STATE_BATTLE_CMD (Skill選択)
  → STATE_BATTLE_SKILL  … スキル一覧表示・選択
      → 自己強化スキル (provoke): 即時実行 → 敵ターン
      → 攻撃スキル + 敵複数: _pending_skill に保存 → STATE_BATTLE_TARGET
      → 攻撃スキル + 敵1体: 即時実行 → 敵ターン

STATE_BATTLE_TARGET (Z決定時):
  _pending_skill が存在 → _execute_active_skill(skill, target)
  _pending_skill が None → 既存の _player_attack フロー (Aid)
```

### 10.4 Warrior の MP について

`data/jobs.json` にて `warrior.mp_die = 2`（初期MP=4）。  
Provoke(MP:3)を1回使用するための最小限のMP設定。レベルアップ時にMP成長あり。

## 12. エンカウント・平滑化仕様（Phase 15）

### 12.1 歩数カウンター

`App.steps_since_encounter` — 最後の戦闘開始（`_start_battle` 呼び出し）以降の歩数。

| タイミング | 操作 |
| :--- | :--- |
| 歩行（移動成功）時 | `steps_since_encounter += 1` |
| `_start_battle()` 呼び出し時 | `steps_since_encounter = 0` にリセット |

### 12.2 エンカウント確率計算式

```
steps = steps_since_encounter
rate  = ENCOUNTER_RATE * min(1.0, (steps - 2) / 7.0)  if steps >= 3  else 0
```

- steps 0–2（戦闘直後3歩以内）: rate = 0 → エンカウントなし
- steps 3–9: rate が 0 から ENCOUNTER_RATE まで線形上昇
- steps 10以降: rate = ENCOUNTER_RATE（通常確率）

## 14. ショップ売却仕様

### 14.1 売却機能の概要

### 14.3 売却価格

```
sell_price = int(item.value * 0.3)
```

アイテムの基本価値（`value`）の **3割** を売却価格とする。

### 14.4 売却制限

- **装備中のアイテムは売却不可**：`item is player.weapon` または `item is player.armor` の場合、`[E]` タグで灰色表示し操作を無視する。

### 14.6 BGM 無効化（Issue #03）

```
flee_rate = min(0.95, FLEE_RATE + total_luk * 0.01)
```

| :--- | :--- |
| コマンド名 | `COMMANDS = ["Aid", "Skill", "Flee"]` |
| Aid の効果 | `_player_attack` を呼び出しダメージを与える（既存ロジック同一） |
| 演出メッセージ | distracts / taunts / harasses / baits / lures / throws debris at / feints against / bluffs at の中からフレームカウントで選択 |
| クリティカル時 | `[CRITICAL!] {player} {verb} {enemy}! -{dmg} HP!` |

### 15.6 Porter 固有スキル「Encourage（鼓舞）」

`JOB_SKILLS["porter"]` に定義された Porter 専用の開始スキル。

**スキル仕様:**

| 項目 | 値 |
| :--- | :--- |
| スキル名 | Encourage |
| MP コスト | 4 |
| `effect_type` | `"encourage"` |
| `power` | 10 |

**計算式:**
```
heal = power + total_luk // 2
for m in party.alive:
    m.hp = min(m.max_hp, m.hp + heal)
```

- 対象: パーティ生存メンバー全員（ターゲット選択不要）
- メッセージ例: `[Encourage] {player} cheers the party! +{heal} HP!`
- `effect_type == "encourage"` はターゲット選択をスキップし直接発動（"provoke" と同様の扱い）

### 15.7 NPC 装備管理（Manage NPC Gear）

`STATE_INV_GIVE_NPC` 画面を「Manage NPC Gear」として刷新。

**フロー:**

4. Z 決定 → 選択 NPC の該当スロットに装備、旧装備はプレイヤー BAG へ自動返却

**表示例:**


## 16. Phase 20: Shop Restock / Party HUD / Genesis Rarity

### 16.1 Shop Restock System

| 項目 | 仕様 |
| :--- | :--- |
| 現在在庫 | `App.shop_stock` (`list[Item]`) |
| 再入荷カウンター | `App.steps_to_restock` |
| 在庫数 | `SHOP_STOCK_SIZE = 15` |
| 再入荷歩数 | `SHOP_RESTOCK_STEPS = 100` |
| レア枠確率 | `SHOP_RARE_SLOT_RATE = 0.08` |

- `_restock_shop(force=True)` で初期在庫を生成する。
- ダンジョンで1歩移動するたび `_tick_shop_restock()` を呼び、`steps_to_restock` を1減らす。
- `steps_to_restock <= 0` または階層移動時に `_restock_shop()` を実行する。
- 基本在庫は現在階層ティアに沿った商品から抽選する。
- 低確率で1枠だけ上位ティア商品またはエンチャント済み装備に差し替える。
- Buy UI は3列×5行のグリッド表示。Sell UI は既存リスト形式を維持。

### 16.2 Party Card HUD

探索中 `draw_status` は4枚のカードHUDを描画する。

| カード | 役割タグ | 枠色 | 内容 |
| :--- | :--- | :--- | :--- |
| 1枚目 | `[REAR]` | `COL_PEACH` | プレイヤー / Porter |
| 2-4枚目 | `[FRONT]` | `COL_LIGHT_GRAY` | NPCメンバー |

各カードには HP/MP の数値とバー、武器/防具短縮名、毒 `[P]` / スタン `[S]` を表示する。4分割で幅が狭いため、名前と装備名はカード幅に合わせて短縮する。空き枠は `Empty` を表示する。

### 16.3 Rarity System

| レアリティ | 色 | 条件 |
| :--- | :--- | :--- |
| `normal` | 白 | エンチャントなし |
| `rare` | 黄 | prefix または suffix のどちらか1つ |
| `epic` | 桃 | prefix + suffix |
| `legend` | 橙 | Master prefix など強力な組み合わせ |
| `genesis` | 青/白明滅 | prefix/suffix なし、高基礎性能 |

`Genesis` は `make_enchanted_weapon` / `make_enchanted_armor` の冒頭で 0.5% 抽選する。生成時は prefix/suffix を付与せず、武器は dice / static bonus、防具は def_bonus を直接上昇させる。

**保存互換:** `systems/persistence.py` では Genesis フラグ、ベース性能、weight_class を保存・復元する。既存データに Genesis フラグがない場合は `False` として扱う。

## 17. Phase 21: Party Item Targeting & Inn Recovery

### 17.1 宿屋のパーティ回復

宿屋 (`TOWN_MENU["Inn"]`) は `self.party.members` を走査し、HP > 0 の生存メンバーのみ HP/MP を最大まで回復する。

| 対象 | 結果 |
| :--- | :--- |
| HP > 0 | `hp = max_hp`, `mp = max_mp` |
| HP <= 0 | 回復しない。`Revive` メニューで蘇生が必要 |

表示メッセージ:
```
Welcome! Rest well.
The party's HP and MP are fully restored.
Fallen members need Revive.  # 戦闘不能者がいる場合のみ
```

### 17.2 アイテム使用対象選択

| 項目 | 仕様 |
| :--- | :--- |
| 状態 | `STATE_INV_TARGET_SELECT = 24` |
| 保留アイテム | `App.pending_use_item` |
| カーソル | `App.inv_target_idx` |
| 対象 | 現在の `party.members`（Player / NPC） |

**フロー:**
```
STATE_INVENTORY
  -> STATE_INV_ACTION [Use]
      -> 対象不要: _do_use(item, player)
      -> 対象必要: STATE_INV_TARGET_SELECT
          -> target 選択
          -> _do_use(item, target)
```

対象不要アイテム:
- `Scroll: Mapping`
- `GrimoireItem`

対象選択アイテム:
- HP/MP回復消費品
- 状態異常治療消費品
- Elixir 等の複合効果消費品

### 17.3 使用可否判定

`_can_use_item_on(item, target)` で以下を判定する。

| 効果 | 使用可能条件 |
| :--- | :--- |
| HP回復 | `target.hp > 0` かつ `target.hp < target.max_hp` |
| MP回復 | `target.hp > 0` かつ `target.mp < target.max_mp` |
| 状態治療 | `target.hp > 0` かつ該当 `status_effects` が 1 以上 |
| 戦闘不能 | 通常消費アイテムでは使用不可 |

無効対象に対してはアイテムを消費しない。

### 17.4 `_do_use(item, target)` 抽象化

`_do_use` は `target=None` を許容し、未指定時は `self.player` を対象とする。

- HP/MP回復、状態治療は `target` に適用する。
- グリモア習得は従来通り `self.player` に適用する。
- Mapping Scroll はマップに適用する。
- 回復発生時は対象カード位置にポップアップを出し、回復SEを鳴らす。
